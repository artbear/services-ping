# Services Ping

Локальный монитор интернета и сервисов с русским интерфейсом для ноутбука.
Проверки выполняются на вашем устройстве; интерфейс открывается в браузере на
`http://127.0.0.1:8765`. Облачный сервер для работы не нужен.

Python 3.10+; обязательных сторонних Python-зависимостей нет.
Android: preview через Termux, без отдельного APK.

## Запуск

Из каталога проекта:

```sh
python3 -m services_ping
```

На Windows:

```powershell
py -3 -m services_ping
```

Откройте адрес, напечатанный в терминале. Для другого порта/каталога данных:

```sh
python3 -m services_ping --port 8766 --data-dir ./data
```

Завершение — Ctrl-C. Программа работает, пока запущен локальный процесс.
Настройки и история находятся в `~/.services-ping` по умолчанию, вне исходников.
`--data-dir` позволяет выбрать другое место. Каталог `data/` исключён из Git.

## Что проверяет

- Интернет: независимые опорные адреса Google, Cloudflare и Яндекс, каждые 3 секунды.
- Сервисы: HTTP(S), TCP или ICMP, по заданному интервалу, по умолчанию 30 секунд.
- Сайты и публичные LLM endpoints: готовые цели без API-ключей и платных запросов.
- Ваши VPS, VPN и BB: добавьте собственные адреса в интерфейсе.

При потере доступа появляется сообщение, замеры сервисов помечаются устаревшими,
проверки интернета продолжаются. После восстановления сервисы проверяются сразу.
По умолчанию обнаружение занимает примерно до 5 секунд: интервал 3 с + deadline 2 с.
Увеличение числа опорных адресов или timeout увеличит это время.

«Частичный доступ» означает, что часть опорных адресов ответила, а часть дала сбой
или неожиданный ответ. «Интернет недоступен по проверкам» означает, что опорные
адреса не ответили: причиной могут быть также DNS, фильтрация или captive portal.

Для HTTP задержка измеряется от начала сетевой операции до заголовков ответа,
включая DNS, TCP и TLS. Для TCP — разрешение адреса и соединение, для ICMP — RTT.
Эти величины измеряют разные этапы и не должны сравниваться как один вид ping.
ICMP требует установленную системную команду `ping`; блокировка ICMP не доказывает
недоступность сайта.

Ответы 401/403 и 429 выделены отдельно: сервер доступен, но API не подтверждён
как работающий. TCP проверяет открытый порт. Для VPN добавьте адрес, доступный
только через ваш туннель; открытый TCP-порт не проверяет UDP WireGuard/OpenVPN.

## Настройки и уведомления

Цели можно добавлять, изменять, отключать и удалять без перезапуска. В настройках
задаются опорные адреса, интервалы, timeout и история. Экспорт/импорт JSON переносит
только настройки. Проверяйте адреса импортируемой конфигурации перед применением.
Не используйте пароли или токены в URL; userinfo в HTTP URL не допускается.

Уведомления браузера включаются отдельной кнопкой и работают пока страница открыта
и браузер разрешает уведомления. Баннеры внутри приложения работают без разрешения.
Опциональные Android-уведомления через Termux:API включаются отдельно в настройках
и работают, пока запущен процесс монитора. Уведомляется изменение доступности
интернета, без рассылки отдельного сообщения на каждую цель при глобальном сбое.

Пауза останавливает новые автоматические проверки. Уже начатые проверки завершаются.
Ручная проверка в паузе запускает один цикл и оставляет приложение на паузе.
Если локальный процесс остановлен, UI покажет потерю связи с монитором отдельно
от состояния интернета.

## Android через Termux (preview)

Установите Termux из источника, указанного в [официальной инструкции](https://github.com/termux/termux-app#installation).
В Termux:

```sh
pkg update
pkg install python git iputils
git clone https://github.com/artbear/services-ping.git
cd services-ping
termux-wake-lock
python -m services_ping
```

Репозиторий приватный: для клонирования нужна ваша авторизация GitHub; также
можно перенести архив исходников на телефон. Откройте напечатанный localhost URL
в браузере **этого телефона**. Для ICMP необходим `ping` из `iputils`.

Для системных уведомлений установите приложение Termux:API из того же источника,
что Termux, затем `pkg install termux-api`, разрешите уведомления и включите
опциональный Termux notifier в настройках. Отсутствие notifier не останавливает монитор.
После завершения при необходимости выполните `termux-wake-unlock`.

Android может ограничивать сеть и останавливать процесс в фоне. Wake-lock и
отключение оптимизации батареи для Termux помогают, но не гарантируют работу при
выключенном экране, force-stop или после перезагрузки. Автозапуска и foreground
service отдельного APK в этой версии нет. Экспортируйте конфигурацию перед удалением
Termux: очистка его данных удалит локальную БД.

Физический Android пока не проверен. Чеклист проверки: установка, доступ к localhost,
потеря/восстановление Wi-Fi, мобильная сеть, VPN, выключенный экран, уведомления,
повторный запуск и сохранность настроек. Официальные ограничения:
[Doze](https://developer.android.com/training/monitoring-device-state/doze-standby),
[фоновые процессы Termux](https://github.com/termux/termux-app#android-12).

## Разработка

```sh
python3 -m unittest discover -s tests -v
```

Браузерные проверки (Node.js 22+, только для разработки):

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

GitHub Actions проверяет Python 3.10/3.12 на Linux, Windows и macOS, а интерфейс —
в Chromium. Физический Android проверяется отдельно по чеклисту выше.

Тесты используют локальные fixtures и не требуют доступа к публичным сайтам.
Документы: [исследование](docs/RESEARCH.md), [план](docs/PLAN.md),
[рецензия плана](docs/PLAN_REVIEW.md), [API](docs/API.md),
[критерии приёмки](docs/ACCEPTANCE.md), [цикл разработки](docs/DEVELOPMENT.md),
[ревью кода](docs/CODE_REVIEW.md), [результаты проверок](docs/VERIFICATION.md).

При locked/corrupt SQLite не удаляйте БД без копии. Остановите монитор и сохраните
каталог данных. Приложение сообщает об ошибке, не сбрасывая настройки молча.
Пока схема БД версии 1; неизвестные версии экспорта отклоняются.

Сервер слушает только loopback и проверяет Host/Origin/CSRF. Это защищает от запросов
чужих веб-страниц; другой процесс вашего пользователя уже имеет доступ к вашим
локальным файлам и не входит в границу защиты. Прокси из переменных окружения для
проверок отключены, системный VPN/маршрут устройства применяется как обычно.
