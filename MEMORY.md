# Память проекта Services Ping

Последнее обновление: 2026-11-11.

## Задача и предпочтения пользователя

Локальное приложение для ноутбука или Android: быстро показывать потерю интернета,
продолжать частые проверки подключения и при наличии доступа интервально проверять
заданные сайты, VPS, VPN, BB, зарубежные LLM-провайдеры, Яндекс и Google.
Нужны настройки, история и сообщения об изменении доступности.

Пользователь запросил полный цикл разработки с сабтредами и параллельной работой:
исследование, план, рецензия через чистый сабтред, реализация, тесты, ревью,
коммит и пуш в приватный GitHub-репозиторий. Отдельное указание от 2026-10-07:
**хранить память проекта в Markdown-файлах**.

Личные адреса инфраструктуры не предоставлены. Они добавляются через интерфейс
и не должны попадать в исходники или память проекта.

## Принятые решения v1

- Python 3.10+, стандартная библиотека, без обязательных Python-зависимостей.
  Backend выполняет проверки на том же устройстве; русский интерфейс открывается
  в браузере через `http://127.0.0.1:8765`.
- Основной выпуск — приложение для ноутбука. Android — Termux preview;
  физический телефон пока не проверен. APK и гарантированная работа в фоне
  не входят в реализованный объём v1.
- HTTP(S) измеряет время до заголовков с DNS/TCP/TLS, TCP — соединение,
  optional ICMP — RTT системной команды ping. Не смешивать смысл этих задержек.
- Каждый probe выполняется в отдельном helper-процессе со сквозным deadline.
  Connectivity и сервисы имеют отдельные ограниченные пулы, scheduler работает
  с интервалом после завершения. Пауза допускает один полный ручной цикл.
- По умолчанию интернет проверяется каждые 3 с, timeout 2 с, сервисы каждые 30 с.
  Опорные адреса: Google generate_204, Cloudflare cdn-cgi/trace,
  Яндекс `https://ya.ru/robots.txt`. Корень Яндекса в проверенной сети даёт 302;
  для опорной проверки выбран robots.txt с ожидаемым 200.
- `online`: все опорные адреса дали ожидаемый HTTP-код; `partial`: есть хотя бы
  один HTTP-ответ, но не все ожидаемые; `offline`: нет HTTP-ответов.
  Это диагностика по адресам, а не доказательство отсутствия физического соединения.
- LLM-провайдеры проверяются публичными GET без ключей и платных запросов.
  `reachable` подтверждает сетевую доступность, здоровье API остаётся неизвестным.
  401/403, 429 и 5xx имеют отдельную классификацию по контракту.
- SQLite хранит настройки, историю по целям и до 1000 событий. Замена настроек,
  удаление истории отсутствующих целей и retention выполняются одной транзакцией;
  runtime обновляется только после commit. Нет выдуманных замеров при offline.
- Localhost API защищён Host/Origin/CSRF, ограничениями размера запроса,
  16 HTTP workers и socket timeout 2 с. Импорт требует подтверждения в интерфейсе.
- Browser notifications включаются отдельно от backend Termux notifier.
  Уведомления — о глобальном offline/восстановлении, с cooldown минимум 10 с.
- Заголовок вкладки браузера показывает состояние интернета и суффикс
  `Services Ping`: `online` — «Есть интернет», `partial` — «Частичный доступ»,
  `offline` — «Нет интернета», `checking` — «Проверяем интернет». Если локальный
  монитор недоступен, заголовок возвращается к «Services Ping» и не утверждает,
  что интернета нет. Надпись на самой странице не дублирует этот префикс.
- Страница подключает `/app.js?v=2` и `/style.css?v=2`. Ответы этих файлов
  содержат `Cache-Control: no-cache`. Монитор читает их с диска при каждом
  запросе из того каталога, откуда запущен процесс; push сам по себе этот
  каталог не обновляет.

## Ограничения и следующие шаги

Публикация выполнена 2026-10-07. Приватность репозитория, `main` по умолчанию,
настройка `origin`, push и совпадение локального и remote SHA проверены.
Не используйте токены из авторизации GitHub в файлах проекта.

GitHub Actions run [37669062876](https://github.com/artbear/services-ping/actions/runs/37669062876)
для опубликованного SHA завершился успешно: 6 комбинаций Python 3.10/3.12 на
Ubuntu/Windows/macOS и Chromium browser smoke. GitHub показал предупреждения,
что `actions/checkout@v4` и `actions/setup-python@v5` используют Node.js 20,
переключаемый на Node.js 24, и о предстоящем изменении `ubuntu-latest`.
Это предупреждения, job прошли. Проверить актуальные поддерживаемые версии actions
при следующем изменении CI.

Физические Android, macOS/Windows ping и разрешения уведомлений на пользовательских
устройствах не проверены. Не объявлять их проверенными по эмуляции viewport.

В локальном игнорируемом `.work/` находятся screenshots, архив первого коммита
`services-ping.zip` и устаревший helper публикации. Они не входят в Git и могут
отсутствовать в другом checkout; архив не включает последующие коммиты памяти.

## Как продолжать

Запуск: `python3 -m services_ping`; на Windows — `py -3 -m services_ping`.
Данные по умолчанию в `~/.services-ping`, можно изменить через `--data-dir`.
Подробности: [README.md](README.md).

Проверки: `python3 -m unittest discover -s tests -v`; для браузера —
`npm ci`, `npx playwright install chromium`, `npm run test:browser`.
В текущей локальной среде браузеры установлены в `/tmp/services-ping-browsers`:
используйте `PLAYWRIGHT_BROWSERS_PATH=/tmp/services-ping-browsers npm run test:browser`.

Стабильные frontend `data-testid` для браузерных проверок:
`internet-banner`, `backend-disconnected`, `add-target`, `target-dialog`,
`target-name`, `target-address`, `target-kind`, `target-group`, `target-save`,
`settings-button`, `settings-dialog`, `settings-save`, `pause-button`,
`check-button`, `import-input`, `export-button`.
Карточки целей выбираются через `[data-target-id]`.
Готовый сценарий: [tests/browser-smoke.mjs](tests/browser-smoke.mjs).
Сообщение frontend-сабтреда подтверждает ранее учтённый smoke desktop/390 px;
это не отдельный новый прогон тестов.

Цикл и ссылки на исследовательские/реализационные/ревью сабтреды:
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
При параллельной работе избегать перекрытия владельцев файлов: в первом цикле
потребовалось восстановить frontend из журнала BB после исчезновения файлов.
Интеграцию и финальные исправления выполнял один поток.
