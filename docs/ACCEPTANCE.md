# Критерии приёмки

## Сценарии пользователя

1. Запуск одной командой Python, открытие локальной страницы без CDN и внешнего backend.
2. На старте немедленно видна проверка интернета; результат появляется после timeout.
3. Ошибка всех опорных адресов вызывает заметный offline-баннер. Один сбой при
   успешном другом адресе показывает частичный доступ, а не полное отсутствие интернета.
4. При offline частые проверки интернета продолжаются независимо от длинных
   интервалов сервисов. Восстановление запускает проверку сервисов немедленно.
5. Адрес собственного VPS/BB добавляется без изменения кода. Редактирование,
   отключение и удаление применяются без перезапуска. Данные переживают перезапуск.
6. HTTP 401/403/429 показаны отдельными статусами. Нельзя показывать «API работает»
   только потому, что пришёл ответ с ошибкой или TCP-порт принял соединение.
7. Для ICMP, TCP и HTTP подписи задержки объясняют измеряемый слой; отсутствующий
   ping даёт unsupported. Shell-метасимволы не могут выполнить команду.
8. История не растёт бесконечно. Offline-пропуск не превращается в свежий успешный
   замер. Удалённые цели не воскресают после завершения старой проверки.
9. Пауза и ручной запуск понятны в UI. Отдельно показана потеря связи с локальным
   процессом, поскольку она не доказывает отсутствие интернета.
10. Экспорт и импорт настроек работают, некорректный импорт не портит текущие
    настройки. Личные адреса/данные не находятся в исходниках и коммите.

## Проверки инженера

- Детерминированные тесты переходов online/partial/offline/recovery и независимого
  расписания, без зависимости от публичного интернета.
- Локальные HTTP/TCP fixtures: успешный ответ, запрет доступа, rate limit, server
  error, редирект, timeout, refused connection, malformed address.
- Total deadline включает DNS и TLS. Число рабочих процессов/потоков ограничено,
  затянувшиеся задачи не накапливаются.
- Local API: Host/Origin, CSRF, размер body, traversal, invalid JSON/config,
  сохранение настроек, HTTP error без traceback.
- Browser smoke на desktop и viewport 390 px: CRUD, settings, import/export,
  история, pause, offline/recovery, backend-disconnected, отсутствие ошибок JS.
- Реальный локальный запуск с публичными целями: сообщить среду и результат.
- CI как минимум Python 3.10 и 3.12, Linux и Windows; macOS при возможности.
- Android runbook отдельно; не заявлять тестирование физического телефона без него.

## Следующие выпуски

Нативный Android APK с foreground service, desktop tray/autostart и OS-события
смены сети, расширенная диагностика DNS/TLS и VPN, долговременная статистика.
Эти пункты не заменяют работающий локальный первый выпуск.
