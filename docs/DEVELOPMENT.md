## Повторение цикла для новых изменений

В начале работы прочитать [память проекта](../MEMORY.md). После существенного
изменения обновить её решения, результаты проверок и следующий шаг.
Память и отчёты сохраняются в Markdown внутри репозитория.

1. Сформулировать наблюдаемый результат и способ проверки.
2. Исследовать только неизвестные платформенные/сетевые ограничения.
3. Обновить план и API при изменении поведения.
4. Отдать рецензию плана в чистый поток с требованиями и файлами, без истории автора.
5. Распределить независимые изменения по владельцам файлов.
6. Проверить поведение детерминированными тестами и локальным запуском.
7. Провести независимое ревью итогового кода, устранить находки.
8. Зафиксировать проверенную версию, отправить в приватный репозиторий.

Не помещать реальные адреса инфраструктуры, экспорт настроек и историю в Git.
CI не обращается к публичным мониторируемым сервисам.
